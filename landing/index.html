AI-Powered Blockchain Fraud Detection

ChainSleuth ingests raw blockchain transfer data, scores every transaction with an Isolation Forest anomaly model, explains the risk deterministically, and commits verified fraud findings to an immutable Solidity smart contract on the Ethereum Sepolia testnet.

01
CSV Ingestion & Validation
The user uploads a blockchain_transactions.csv file through the dashboard. The backend's ingestion service validates required columns (tx_hash, amount, sender, …), deduplicates rows by tx_hash, and persists records to the async SQLite database via SQLAlchemy 2.0.
# backend/app/services/ingestion.py REQUIRED_COLUMNS = {"tx_hash", "amount", "sender", "receiver", "timestamp"} async def ingest_csv(file_path, db: AsyncSession) -> IngestResult: df = pd.read_csv(file_path) _validate_columns(df) # raises IngestionError if missing df = df.drop_duplicates("tx_hash") await _bulk_insert(df, db) # async batch write
02
Feature Engineering
Each transaction is transformed into a 8-dimensional feature vector by the Pandas ETL layer. Features include: log-normalized amount, sender/receiver frequency, hour-of-day, value vs. address mean deviation, and inter-transaction time delta. This is what the ML model actually sees — not raw strings.
# Derived features fed into Isolation Forest features = [ "log_amount", # log1p(amount) — skew correction "sender_freq", # how often sender appears "receiver_freq", "hour_of_day", "amount_z_score", # std deviations from mean "tx_velocity", # txns per sender per hour "amount_to_addr_ratio", "time_delta_seconds", ]
03
Isolation Forest Anomaly Scoring
An Isolation Forest (scikit-learn) is trained on unlabeled transaction data. It builds random trees and measures how quickly each point is "isolated" from the rest — anomalies require fewer splits. The model outputs an anomaly score in [-1, 0], which is then mapped to a human-readable risk tier:
Critical
High
Medium
Low
# backend/app/ml/model.py def if_score_to_risk(score: float) -> str: if score < -0.15: return "critical" if score < -0.08: return "high" if score < -0.02: return "medium" return "low"
04
Dashboard & Explainability
Risk scores and feature contributions are surfaced in the React dashboard. The Alerts page shows all critical and high transactions. The Transaction Detail view explains which feature drove the score — e.g. "amount_z_score is 4.2σ above average" — giving deterministic, human-readable explainability without a separate XAI library.
05
On-Chain Audit Commit
Analysts can flag a transaction for permanent record. The backend calls Web3AuditService, which computes a keccak256 hash of the transaction data, then calls ChainSleuthAudit.sol on Sepolia. The event is immutable — no one can delete or alter the fraud finding.
// contracts/ChainSleuthAudit.sol (simplified) event FraudCommitted( bytes32 indexed txHash, address indexed reporter, string riskLevel, uint256 timestamp ); function commitFraud(bytes32 txHash, string riskLevel) external onlyRole(REPORTER_ROLE) { emit FraudCommitted(txHash, msg.sender, riskLevel, block.timestamp); }

Smart Contract
Immutable Audit Trail on Ethereum

The Solidity contract is the final truth layer. Once a fraud hash is committed, it cannot be deleted, tampered with, or disputed — it lives on Sepolia's blockchain forever.

Key Design Choices
  • OpenZeppelin AccessControl — only accounts granted REPORTER_ROLE can write
  • keccak256 hashing — tx data is hashed before committing to minimise gas
  • Event-driven storage — fraud records are emitted as events, not stored in mappings, for cost efficiency
  • No upgradeability — intentionally immutable to guarantee audit integrity
